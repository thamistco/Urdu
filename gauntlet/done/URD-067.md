## URD-067 — choti-he and do-chashmi-he share a teaching group and a visual family but have no confusableWith link

**Status: RESOLVED — decided, no link. The omission is now a written decision.**

### The question

`choti-he` (ہ) and `do-chashmi-he` (ھ) sit in teaching group 8 — the file's own
comment calls it "the h family" — are taught back to back, and neither names
the other via `confusableWith`. The item asked for that to be settled on
purpose either way, against the real rendered glyphs rather than the glyphs'
Unicode names.

### The answer

No link. `do-chashmi-he` is not `choti-he` plus a mark.

The criterion is the one `confusableWith`'s own doc comment already states: a
link is warranted where a letter's curated note describes the shared shape —
"Same bowl as be, but three dots below", "One dot above the ح (baṛī he) curve",
"Kaaf with a second stroke on top". That turns out to be a real corpus
invariant: **all 16 declared pairs are documented that way from one side or the
other** (15 from the variant's note, `baRi-ye ~ choti-ye` from the base's).
Neither note here makes that claim. `do-chashmi-he`'s "The h with two eyes"
names its own eyes, not a mark added to ہ's outline, and `choti-he`'s note
names ح, not ھ.

Rendered at the letter lab's own `urduGlyph(72)` in the app's own Nastaliq, the
glyphs agree: ھ cannot be got by adding anything to ہ, the way khe is baṛī he
plus a dot or gaaf is kaaf plus a stroke. Its two eyes are the body of a wider,
flatter letter, near identical across its four forms, where ہ is compact and
its four faces differ sharply — which its own note already says.

Reproduce the comparison with:

```
node scripts/measure-glyph-pair.js choti-he do-chashmi-he --png out.png
```

### Two quantitative routes that fail

Both are recorded in `letters.ts` and in the harness's own header, because both
are tempting and both give the wrong answer.

**The shipped trace masks.** Scored on `src/data/glyphMasks.ts`, the pair comes
out at 0.443 mean IoU across the four forms — effectively tied with the
genuinely confusable `baRi-he ~ khe` at 0.458, and inside the declared range of
0.300–0.844. Taken at face value it says "link". It is the wrong instrument:
`generate-glyph-masks.js` frames every glyph in its own square scaled to its own
longest edge, because tracing needs each letter to fill its own card, and that
normalisation discards exactly the scale difference in question. It also ranks
114 *undeclared* pairs above this one, so it is not the corpus's criterion for
anything.

**Rendered glyph width.** This one was believed and committed before it was
checked properly, and it was wrong. Measuring the two pairs nearest to hand
suggested a clean rule — a mark adds ink to an outline it does not widen, so a
base-plus-mark pair measures 1.00x width in every form:

| pair | max width ratio | max ink ratio |
| --- | --- | --- |
| `baRi-he ~ khe` (declared) | 1.00x | 1.17x |
| `kaaf ~ gaaf` (declared) | 1.00x | 1.15x |
| `choti-he ~ do-chashmi-he` | 2.47x | 1.86x |

Run across all 16 declared pairs it misclassifies eight of them, because a mark
on a narrow glyph dominates its bounding box:

| declared pair | max width ratio |
| --- | --- |
| `alif ~ alif-madda` | **4.00x** |
| `noon ~ noon-ghunna` | **2.29x** |
| `choti-ye ~ baRi-ye` | 2.06x |
| `be ~ pe` | 1.41x |

`alif ~ alif-madda` is further apart than the pair this rule was being used to
rule out. The rule would have unlinked eight existing pairs.

Overlap (IoU) at true scale was tried too and is not reported by the harness at
all: it swings on alignment. Centred text shifts sideways when a mark widens the
advance (kaaf/gaaf's initial forms differ by 15px from that alone), and aligning
bounding boxes instead drags a dotted glyph's body out of place — `baRi-he ~ khe`
reads 0.90 or 0.11 depending which you pick.

### Two corrections to the item

- The item says `khe` links to `baRi-he` "despite being in a different group
  entirely". Both are group 2. Every one of the 16 links is same-group, so
  sharing a group is a property of all of them rather than a reason for any one
  — now asserted as a test.
- The pair *is* genuinely easy to confuse in use, both romanising as "h". That
  is sound and function, which URD-053 handled in these notes. `confusableWith`
  is documented as visual shape, and a link would put the pair into
  `letterContrast`'s head-to-head drill, which exists for telling near-identical
  outlines apart.

### Verification

Three tests in `src/data/letters.test.ts`, in the shape of the existing
`confusableWith`-bucket invariants:

1. `choti-he` and `do-chashmi-he` sit in different buckets, and neither note
   makes the shared-shape claim a link would assert.
2. Every `confusableWith` link stays inside one teaching group.
3. Every declared pair has its shared shape written down in a note, from one
   side or the other.

Each was broken on purpose and watched to fail (non-negotiable 2):

| mutation | fails |
| --- | --- |
| add `confusableWith: 'choti-he'` to `do-chashmi-he` | bucket test, documentation test, and URD-062's existing count (13 → 14) |
| point `pe` at `jeem` (group 1 → 2) | group test, documentation test |
| strip "Daal with…" from `zaal`'s note | documentation test alone |

The third matters most: it shows the documentation test is not vacuous, and the
first shows the invariant does real work — anyone who wants this link must first
write the sentence that justifies it.

`check:all` — all 30 steps pass.

### Also added

`scripts/measure-glyph-pair.js`, the harness that produced the evidence, so the
decision can be re-checked rather than re-argued. A companion tool like
`measure-image.js`, not part of `check:all`. It prints no verdict; its header
records why the numbers it prints cannot give one.
