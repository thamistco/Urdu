## URD-027 — 68% of the sentence pool is never drawn by any lesson
attempts: 0
files: src/exercises/generator.ts, src/data/sentences.ts, scripts/
definition of done: a coverage check (mirroring check:coverage's existing
  word-level guarantee) proves every sentence in SENTENCES is drawn by at
  least one sentences lesson at its level, or documents an explicit,
  deliberate exemption for the ones that are not. Measured today: 81 of
  256 sentences (31.6%) are ever drawn — beginner 22/67, elementary 16/69,
  intermediate 24/63, advanced 19/57 — because each lesson does an
  independent `seededShuffle(pool, lesson.id).slice(0, lesson.size)` with
  no allocation across lessons at the same level, the same shape of gap
  vocab had before wordIds replaced random topic sampling.
verify: a new check:sentence-coverage script (or an addition to
  check-coverage.js) exits 0 only when every sentence is reachable.
notes: Found by CURRICULUM CRITIC reviewing 0453fa7, who was explicitly
  asked to check whether this commit inherited vocab's coverage fix rather
  than assume it did — it did not. Predates this commit (the draw
  mechanism is unchanged; only `size` moved 5→8), but this is the same bug
  class gauntlet/ROLES.md names as the project's founding motivation
  ("a full playthrough... reached 608 of its 2,281 words"), now confirmed
  present for sentences too and previously unmeasured.

  FOOTNOTE from URD-026 (grammar-concept readiness filter): re-measure
  before attempting this — URD-026's fix changed WHICH sentences are
  reachable without changing the aggregate share. Reachability is now
  81/256 (31.6%) still, but 41 of the original 81 reachable sentences were

  The old per-level reachable-id lists this item's own numbers imply

  RESOLVED: `sentencesForLesson` (`generator.ts`) replaces the old
  independent-per-lesson draw. It walks a level's `sentences`-kind lessons
  in path order and has each one exclude whatever an earlier sibling
  already drew (recursive, terminating since it only ever descends to
  strictly-earlier siblings, verified by hand-trace and live for
  intermediate's real 4 siblings). This raises coverage to each level's
  real ceiling — the sum of its lessons' sizes — not to 100%: total lesson
  capacity per level (16-32) is well under each level's pool (57-69), so
  full coverage needs more lesson capacity, a curriculum decision outside
  this item's own file scope (no `units.ts`). Measured: 96 of 256
  sentences reachable (37.5%), up from 81/256 (31.6%), with the achievable
  ceiling reached exactly at every level (24/24, 16/16, 32/32, 24/24).

  A new `scripts/check-sentence-coverage.js`, wired into `check:all` (a
  real CI gate, unlike `check:shape`), asserts the ceiling is actually
  reached at every level and reports the remaining capacity-bounded gap
  explicitly rather than claiming false 100% — the "documents an explicit,
  deliberate exemption" half of this item's own definition of done, made
  concrete and machine-checked.

  Along the way, found and fixed an unrelated pre-existing latent bug in
  `scripts/check-all.js`'s own workflow-parser regex: `[a-z:]+` did not
  admit a hyphen, so `npm run check:sentence-coverage` (the first
  hyphenated script name in the whole `check:*` family) silently parsed as
  `npm run check:sentence`, a script that doesn't exist — `check:all`
  would have failed outright the moment this step's workflow line was
  added, not silently skipped it. Fixed to `[a-z:-]+`; confirmed by
  induced failure that the old regex really did mis-parse it and that no
  existing script name was affected before (none had a hyphen).

  CURRICULUM CRITIC found two MAJOR findings, both addressed:

  (1) the 62.5% gap left by the ceiling was not uniform — it concentrated
  on late-taught grammar concepts, and two (g-future, g-compound) had
  literally zero sentences shown outside their own one-shot grammar lesson,
  because a uniform random draw gives a late concept exactly as many
  lottery tickets as an early one despite far fewer eligible sibling
  lessons to be drawn into. Fixed in the same function: each lesson's draw
  now first gives one slot to every concept tagged in its readable pool
  that no earlier sibling at the level has represented yet (deterministic
  order), before falling back to the previous random fill for the rest.
  Verified directly: 0 of 25 real grammar concepts now have zero
  sentences-lesson reinforcement (was 2), g-future and g-compound each
  moved from 0/6 to 1/6, with the level ceiling unchanged (this
  redistributes which sentences fill the fixed capacity, it does not raise
  the capacity). New regression test added
  (`generator.test.ts`); induced failure (removing the concept-priority
  loop) reproduced g-future's exact 0/6 before the fix was restored.

  (2) a cheap, in-band way to raise the ceiling itself exists and wasn't
  explored — `S()`'s default `size` (8) could go to 10 without breaching
  check:shape's 8-minute band (verified: 45s/sentence via
  `sentenceReinforceClimb`, size 10 = 450s = 7.5 min), moving aggregate
  coverage from 96/256 (37.5%) to 115/256 (44.9%). This requires touching
  `units.ts`, outside this item's own file scope, so filed forward as
  URD-048 rather than done here.
