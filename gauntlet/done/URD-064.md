## URD-064 — soak's --track flag accepts any string and writes it straight into storage
attempts: 0
files: scripts/soak.js
definition of done: `const TRACK = arg('track', 'both')` (`soak.js`) does no
  validation against the real `LearnTrack` enum (`'script' | 'roman' |
  'both'`, `useSettingsStore.ts`) — a typo like `--track roams` now writes
  `{track: 'roams'}` straight into `harf-settings` via URD-051's
  `trackSettingsFor`, and `generator.ts`'s own `track !== 'roman'` checks
  treat anything that isn't literally `'roman'` as script-teaching, with no
  error anywhere in the chain. Fail loudly at startup instead: reject an
  unrecognised `--track` value by name, before the browser ever opens.
verify: `npm run soak -- --track roams` exits non-zero with a message
  naming the bad value and the three it accepts, rather than silently
  running with a track the app itself doesn't recognise.
notes: Found by THE CRITIC reviewing URD-051 — the same "silently wrong,
  not caught" shape that item fixed, just one layer up (the CLI arg itself,
  rather than what `enterAsGuest` did with it once parsed). Pre-existing:
  the unchecked `arg()` call was already there before URD-051, which only
  gave the string somewhere real to land. Not blocking for URD-051 — every
  value `soak.js` itself ever passes is one of the three valid strings, and
  `check:soak-track` only exercises those three, so this is a hardening
  item for a human mistyping the flag, not a defect in generated content.

RESOLVED. `soak.js` gained `VALID_TRACKS = ['script', 'roman', 'both']`
and an immediate check right after `TRACK` is computed: an unrecognised
value prints the bad value and the three accepted ones, then exits 1 —
before `findRunner()`'s dist/Chromium checks, let alone a real browser
session. A new check script, `scripts/check-soak-track-arg.js` (wired up
as `npm run check:soak-track-arg`), spawns the real `soak.js` and asserts
this behaviour directly, without needing a build or a browser.

Verified the exact queue-item command first: `npm run soak -- --track
roams` prints `soak — unrecognised --track "roams"; expected one of:
script, roman, both` and exits 1. Confirmed all three real values and the
unset default still pass.

Dispatched THE CRITIC via the WIP-commit review pattern, who found two
real MAJORs — both fixed and re-verified.

**MAJOR (fixed): the new check script's fixed 5-second `spawnSync`
timeout was not reliable, and leaked zombie Chromium processes on every
ordinary run.** The check's own first draft assumed `--lessons 0` made a
valid `--track` run "exit immediately after passing validation." THE
CRITIC measured this directly and found it false: even with `--lessons
0`, `soak.js`'s IIFE still launches a real headless Chromium, serves
`dist/`, and completes guest onboarding before ever checking the loop
bound — about 10 real seconds, not immediately. The fixed 5s timeout hit
on every run in this environment, not only a slow one, confirmed by
direct timing (`10.2s` for a bare `--lessons 0` run; the check itself
took `15.6s`, hitting `ETIMEDOUT` on all three valid-track spawns), and
`spawnSync`'s timeout kill only ever reached the immediate `node`
process, orphaning the Chromium it had already launched — confirmed live
via `ps`, ten zombie `chrome`/`chrome_crashpad_handler` processes left
after every run. The check still happened to pass, since its assertion
only greps for one string in truncated output and never inspects
`result.signal`/`result.error`, meaning it could not have told "a valid
run completed cleanly" apart from "a valid run was force-killed
mid-flight" — a real future regression in that direction would produce
an identical, silently-missed signature. Rewritten to not need a full run
at all: `runUntilOutput` spawns detached (`detached: true`), resolves the
moment the child's very first line of output arrives (the rejection
message, or the startup banner proving validation passed — confirmed by
reading `soak.js` top to bottom that nothing prints before the `--track`
check), and kills the whole process *group* (`process.kill(-child.pid,
'SIGKILL')`, not a plain `.kill()`, which again only reaches the
immediate process) the instant that happens. Re-verified: a clean run now
takes ~21s total across all 8 spawns (comfortably real, not padded) with
zero zombie processes before or after, confirmed by `ps` both times; the
same mutation THE CRITIC would have used (removing the validation block
entirely) correctly fails the check with 4 named problems and, again,
zero process leaks afterward.

**MAJOR (fixed): `--track=value` (equals-sign syntax) silently fell
through to the default, exit 0, no error anywhere — the exact bug class
this item exists to close, reached through an equally ordinary CLI
convention instead of a typo.** `arg()`'s own parsing only ever checked
`process.argv.indexOf('--track')`, which never matches the single token
`--track=roman`. Reproduced live before fixing: `node scripts/soak.js
--track=roman --lessons 0` printed `track both`. This is a pre-existing
limitation of `arg()` shared by every flag in the file, not introduced by
this diff, but directly undercuts what this item claims to have closed
for the one flag it's about — THE CRITIC recommended fixing `arg()`
itself as "small, low-risk" rather than leaving the gap noted. Fixed:
`arg()` now checks for a `--name=value` token first (an empty value after
`=` deliberately falls through to `fallback` rather than becoming an
unexpected empty string), and `has()` recognises the same form. Verified
every real flag (`seed`, `lessons`, `track`, `start`, `require`) with both
space-separated and `=`-separated forms, plus the space form still
working unchanged and an empty `--track=` correctly falling back to the
default. Re-verified the original repro is closed: `--track=roman
--lessons 0` now prints `track roman`; `--track=roams` now prints the
same rejection the space-separated form does.

Verified: `npx tsc --noEmit`, `npx vitest run` (273/273, unchanged — a
plain script, not unit-tested), `npm run lint`, `npm run format:check`,
`node scripts/check-soak-track-arg.js` (clean, both space- and
equals-separated forms, no process leaks before or after), `npm run
check:soak-track` (URD-051's own, unrelated mechanism — unaffected,
confirmed clean), and a full `npm run check:all` on the final commit.
