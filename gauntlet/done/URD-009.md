attempts: 0

definition of done: The daily goal labels are derived from the course's actual
  XP-per-minute rather than a constant that no longer holds. `achievements.ts:69`
  and `SettingsScreen.tsx:400` label the goals with minute figures computed at
  12.54 XP/min. After URD-A02 attempt 1 the course yields 3.95 XP/min, so the
  "20 min a day" goal is really 30.4 minutes. A test computes the rate from the
  real path and asserts each label is within a minute of it.
verify: npm test -- src/lib/achievements.test.ts
notes: Found by THE CRITIC on URD-A02, which is the pattern worth noticing: a
  curriculum change moved a number three files away and nothing connected them.
  Deriving the rate is what stops that happening the next time the path moves.

  RESOLVED: measured the real rate directly (walking every non-reading/
  dialogue lesson through the actual exercise generator, script track) —
  4.77 XP/min today, having already moved once before this item was worked
  (3.95 XP/min, measured when the item was filed) from the original 12.54
  assumption. Re-tuned `DAILY_GOALS`' `minutes`/`desc` fields by hand to
  match: calm 3→4 min, steady 7→8, serious 12→15, intense 20→25. `xp`
  values (20/40/70/120), the number `HomeScreen.tsx`'s progress ring and
  `useProgressStore.ts`'s real XP tracking actually use, were left
  unchanged — only the descriptive minute label was stale.

  Added `src/lib/achievements.ts` (`courseXpPerMinute()`,
  `minutesForGoalXp(xp)`) and `src/lib/achievements.test.ts`, which holds
  the hand-set `minutes`/`desc` honest against the real, freshly-computed
  rate — within a minute, per this item's own spec — rather than computing
  them live at import time: the alternative is a full-course
  exercise-generation pass on every app load, and this project has already
  been burned by trusting a Node-script timing (150ms) as evidence about a
  phone's JS engine's real cost (`check:shape`'s own unmemoised
  `buildLessonExercises` calls, URD-011). A drift is a loud, CI-blocking
  test failure instead — a real but softer guarantee than a value that
  literally cannot go stale, and the code says so plainly rather than
  overclaiming an equivalent to `levelTitle`'s different (formula-gated,
  not content-gated) precedent, per THE CRITIC's own finding below.

  Neither `SettingsScreen.tsx` nor `OnboardingScreen.tsx` needed a direct
  edit — both already read `g.desc`/`g.xp` off the shared `DAILY_GOALS`
  array, so fixing the data fixed every display site.
