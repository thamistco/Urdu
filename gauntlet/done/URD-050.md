## URD-050 — meaningPick can never offer another sentence as a distractor, at all
attempts: 0
files: src/exercises/generator.ts, src/data/art.ts
definition of done: URD-030 made the grammar climb's distractor pool
  concept-aware, but measured directly (not assumed): its fix only ever
  reaches `wordFromMeaning` exercises. `meaningPick`'s call to
  `distractorsFor` sets `distinctCue: true`, and `cueOf` (`data/art.ts`)
  falls through to `emo:${word.emoji}` for any sentence-derived `Word` —
  every sentence in the course shares the identical literal `'📝'` emoji,
  with no per-sentence override the way real vocabulary gets `NUMERALS`/
  `COLOURS`/`WORD_ICON`. `distinctCue`'s `usedCues` set is seeded with the
  *correct answer's own* cue before any candidate is even considered, so
  when the answer is itself a sentence, every other sentence — same
  concept or not, `preferred` pool or plain — collides with that seed and
  is rejected outright. Measured: 0 of 292 grammar-climb `meaningPick`
  exercises offer a same-concept distractor, both before and after
  URD-030's fix — not because the pool isn't concept-aware (it now is,
  identically to `wordFromMeaning`'s pool), but because `meaningPick`
  structurally cannot offer *any* sentence as a distractor for a
  sentence-answer, regardless of pool. Give sentences some way to be
  cue-distinct from one another (e.g. keying `cueOf` for a `topic ===
  'sentences'` word off something more specific than the shared emoji —
  its own `id`, say, the same way `NUMERALS`/`WORD_ICON` key off a word's
  `id` today for the words that need it) without breaking whatever
  `distinctCue` protects against for real vocabulary (a picture-based
  question showing two options with the same picture).
verify: a script or test measuring the same-concept-distractor rate
  specifically among `meaningPick` exercises (as `check:grammar-
  distractors.js`, added by URD-030, already separates by kind) reports
  it above 0%, without `check:answerable`'s own picture-distinctness
  rules regressing for real vocabulary.
notes: Found while verifying URD-030's own fix landed where the item's

  what its own definition of done asked ("the pool ... no longer the

  Not BLOCKING for URD-030: every `meaningPick` exercise sampled remains

  ceiling on how far the improvement can reach was found, not a bug.

RESOLVED. `cueOf` (`data/art.ts`) now returns `sen:${word.id}` for any
`Word` with `topic === 'sentences'` — unique per sentence, the same way
`NUMERALS`/`WORD_ICON` already key a real word's cue off its own id where
the shared-emoji fallback would otherwise collide two things that do not
look alike. This unblocks `distractorsFor`'s `distinctCue` guard for every
caller whose pool is `SENTENCE_WORDS`, `meaningPick` included. Measured:
`npm run check:grammar-distractors` — grammar-climb `meaningPick` went from
0/292 (0%) to 292/292 (100%), matching `wordFromMeaning`'s own rate and
saturating at the identical `DISTRACTORS - 1` cap URD-030 put in place (no
change needed there — the cap's own code is untouched, only its
`meaningPick` reachability). The plain `sentences`-kind lessons this
function is shared with (not this item's own scope, but the same shared
`distractorsFor` path) measured similarly: 570 of 576 (99.0%) concept-tagged
exercises now get a same-concept distractor, up from a mix of 0% (meet
turn) / high (recall turn) before.

A sentence's own `WordArt` icon (`components/Illustration.tsx`) still
renders the literal shared '📝' regardless of this fix — the new cue is
what generation-time distractor selection compares, not what the screen
draws. Confirmed safe for the two exercise kinds that DO enforce
`cueOf`-distinctness in `check-answerable.js` (`listenTap`, `matching`):
`matching`'s board is built only from vocabulary-lesson `picks`/`pool`,
never `SENTENCE_WORDS`; `meaningPick`/`wordFromMeaning` (the only two kinds
this item touches) are never checked for shared cues there at all — every
option already carries its own English caption underneath the icon, so a
repeated icon never made either kind unanswerable, only less decorative.

**THE CRITIC, one BLOCKING, found and fixed.** The safety argument above
— "sentence-topic words never reach listenTap/matching" — was true for
`matching` but false for `listenTap`: the review loop's `turn === 1` branch
(`generator.ts`) forces `wordExercise`'s variant to `2` (`listenTap`)
unconditionally for whatever due item lands there, and a due item can be a
previously-graded sentence just as easily as a real word (`itemsOf` tags a
sentence answered via any word-kind exercise the same `{type: 'word'}` way,
and `dueQueue` surfaces it back untouched). Before this fix, a sentence's
`distinctCue` pass on `SENTENCE_WORDS` always failed (shared emoji) and
fell through to real, visually-distinct vocabulary as `listenTap`'s
distractors; after, sentences satisfy each other directly, so `listenTap`
rendered four *other sentences* — every option showing the identical
literal '📝' icon, silently defeating `check-answerable.js`'s own
`distinct(options.map(cueOf))` guard against exactly that, because that
check never simulates a due queue and so never reaches this path at all.
THE CRITIC measured this directly (a due queue seeded with real sentence
ids against 60 real review lessons, both tracks, 3 visits each): 492 of 492
sentence-answered `listenTap` exercises had all 4 options be other
sentences. Independently reproduced the same way (492/492, revert-verified:
0/0 with the fix restored) and fixed by routing a sentence-topic due item
to variant 1 (`meaningPick`) instead of 2 in that one branch — the same
convention `sentenceReinforceClimb`'s own `meet` turn already uses for a
sentence, for the identical reason. Added a permanent regression test
(`generator.test.ts`, since `check-answerable.js` structurally cannot catch
this — it never populates a due queue) asserting a sentence due for review
never becomes a `listenTap` exercise; revert-verified it fails with the
exact predicted shape.

**CURRICULUM CRITIC, no BLOCKING or MAJOR, one positive finding worth
recording.** Confirmed via `MeaningPickExercise` (`WordChoiceExercises.tsx`)
that the identical decorative icon across four sentence options was never
load-bearing (check-answerable.js's own guard for this kind checks meaning
and urdu text only, not cueOf) and is unchanged by this fix either way —
not a regression, not something this item could have made worse. More
substantively: generated real before/after examples for g-plurals and
g-comparative and read the actual English on screen — before this fix, a
same-concept sentence question's distractors were single unrelated
vocabulary words (e.g. "honourable" / "currency" / "garden" as the wrong
answers for a full comparative sentence), answerable by shape alone without
reading a word of Urdu; after, the distractors are genuinely same-
construction sentences (three other comparatives, one unrelated anchor),
which is a legitimate test of the grammar concept in a recognition
question, not a vocabulary-recall trap — judged a stronger result than
this item's own framing ("adds variety") gives it credit for.
