## URD-068 — traceTheLetter's solver dead-ends on a real letterTrace screen

**Status: RESOLVED**

### The failure

`npm run soak -- --seed 4 --lessons 8` dead-ended on a `letterTrace` screen —
four identical screenshots of "be · start / trace the letter", the caption
"Draw over the grey letter" and an untouched grey glyph sitting unchanged
across every retry, until the idle counter (4) fired.

### Root cause

`traceTheLetter` guessed the drawing surface from the *caption's* bounding box:

```js
const area = { x: box.x - 4, y: box.y - 330, width: 348, height: 330 };
```

The caption is a short centred line, so its left edge says nothing about the
pad's. Measured on the real dead-end screenshot (`.soak/1-dead-end.png`,
412px viewport) by replaying the clip offline against the saved PNG:

| | measured |
| --- | --- |
| pad (parchment card) | x 34–378, y 126–470 |
| computed clip | x 133–411 (348 wide, truncated to 278 by the viewport), y 112–442 |
| dark samples in that clip | 1578 |
| …that were page background **outside** the pad | **842 (53%)** |
| topmost dark pixel — where `mouse.down()` fires | **(135, 114), lum 24.7** |

The clip overhung the pad above and to the right while missing its entire left
third, so more than half of what it read as "glyph" was the dark page
background (lum 24.7 against parchment 220 and glyph 193). The walk starts at
the topmost dark pixel, and that pixel was background 12px *above* the pad.

So `page.mouse.down()` landed off the drawing surface. react-native-web never
granted the pad's responder, no stroke was recorded, and `TracePad` kept
`Clear` and `Check` `disabled={strokes.length === 0}`.

### Why it hid for so long

`tap()` uses `click({ force: true })`, which bypasses actionability checks — so
clicking the **disabled** `Check` button returned `true`. `traceTheLetter`
returned that value, `answer()` recorded a `letterTrace` as answered, and the
exercise counter advanced on a screen the driver had never touched. Debug
output said `CHECK button tapped: true` on the very screens that were failing.

It was intermittent rather than total because the bad rect still overlapped the
pad: when the glyph reached high enough, the topmost dark pixel landed on the
pad and the trace worked. That is why lessons 1–5 progressed through 20
traces before a screen where it didn't.

### The fix

`TracePad` already labels its surface for screen readers
(`accessibilityLabel="Drawing area. Trace …"`), which react-native-web renders
as a real `aria-label`, so the element can be asked for its own box instead of
being inferred:

```js
const pad = await onScreen(page.locator('[aria-label^="Drawing area"]'), 0, 900);
const box = await pad.boundingBox();
return { x: box.x + 4, y: box.y + 4, width: box.width - 8, height: box.height - 8 };
```

The 4px inset clears the pad's own 2px ink border, which is darker than the
glyph and would otherwise be the topmost "glyph" pixel every time.

Second, `traceTheLetter` now asserts the stroke registered — a real stroke
removes the caption — before tapping `Check`:

```js
const drew = !(await onScreen(page.locator('text=/Draw over the grey letter/i'), 0, 900));
if (!drew) return false;
```

Without it the driver cannot tell a real answer from a force-click against a
disabled button. That false success is exactly what hid this bug, and it would
have hidden the next one.

The pixel walk moved into `glyphStroke()` and the rect into `traceArea()` to
stay inside this file's 45-line function limit.

### Verification

Definition of done, run for real:

```
$ npm run soak -- --seed 4 --lessons 8
soak — 0 lessons completed, 8 attempts, 101 exercises answered.
  exercise kinds exercised: letterTrace 23 · letterForm 25 · letterPick 28 · letterSpot 18 · letterContrast 7
  Nothing broke. Seed 4.
```

All 23 trace screens report a pad-derived rect (`[trace] pad 36,128 340x340 →
220 pts`) matching the measured pad, with every sampled point inside it.

**The new guard was broken on purpose and watched to fail** (non-negotiable 2).
Temporarily restoring the caption-derived rect:

```
[trace] pad 133,112 348x330 → 220 pts
[trace] no stroke registered — pointer missed the pad
✗ unanswerable screen — nothing on screen could be acted on:
  ✕ / TE · END / Trace the letter / ‏ـت / Draw over the grey letter / CLEAR / CHECK
```

It fires on the old geometry and the run fails loudly at exercise 3, instead of
silently faking 90 answers and dead-ending. That also confirms the causal
chain: old rect → pointer misses pad → no stroke → disabled Check.

### What this does not fix

Zero lessons completed, unchanged. That is the hearts-economy attrition already
measured and attributed to URD-006 in `soak.js`'s own comments — a real trace
answer can still be graded wrong, and `wrongOnPurpose` still spends hearts on
purpose. This item scoped the solver's dead end, not lesson survival.
