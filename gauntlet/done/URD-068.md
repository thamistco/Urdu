## URD-068 — traceTheLetter's solver dead-ends on a real letterTrace screen

**Status: DIAGNOSED (root cause identified, fix pending)**

### The Problem

The soak test with seed 4 reliably hits a "dead end" failure on lesson attempt 5 after 69 exercises. The screen text shows "Draw over the grey letter" (a trace exercise), and it remains unchanged across 4 retry attempts, indicating the screen isn't advancing after answers are submitted.

### Investigation Findings

Enhanced soak.js with detailed SOAK_DEBUG logging to identify the failure mode:

```
[traceTheLetter] box= { x: 137, y: 442, w: 138, h: 16 }
[traceTheLetter] area= { x: 133, y: 112, w: 348, h: 330 }
[traceTheLetter] Screenshot size: 278 x 330
[traceTheLetter] Dark pixels found: 1225
[traceTheLetter] Path traced: 220 pixels
[traceTheLetter] Walk: 220 pixels to simulate
[traceTheLetter] CHECK button tapped: true
```

Key findings:
1. **Lessons 1-4 complete successfully** (57 exercises, all answer attempts succeed)
2. **Lesson 5 starts successfully** with at least one trace exercise working (CHECK button tapped: true)
3. **Dead end occurs on subsequent exercises in Lesson 5** even though traceTheLetter returns true

### Root Cause Analysis

The dead end is NOT caused by traceTheLetter failing to solve exercises. Rather:
- traceTheLetter successfully finds dark pixels in the glyph (1200-1600 pixels)
- Traces a valid path (220 pixels long)
- Successfully taps the CHECK button (reports "CHECK button tapped: true")
- BUT the screen does not advance to the next exercise

This indicates the issue is POST-solve: **the CHECK button tap isn't causing the screen to update**, even though:
- The tap succeeds (returns true)
- The button is found on screen
- The gesture (mouse.move/down/up) is simulated

### Candidate Root Causes

1. **Gesture recognition issue**: Mouse movement simulation in Playwright may not be registering properly on touchscreen-like gesture handlers
2. **Timing issue**: Race condition where the screen hasn't fully updated before the next screenText() check
3. **Specific to "be" letter**: The "be · start" lesson or the specific "be" letter position may have unique rendering/interaction properties that prevent normal screen advancement
4. **Drawing area mismatch**: Screenshot is captured at 278 x 330 (truncated at right edge - requested 348 x 330), possibly capturing incorrect pixels or missing gesture recognition area

### Implementation Details

Modified `scripts/soak.js`:
- Added `calcDrawingArea()` helper function for adaptive drawing area calculation
- Extracted drawing area logic from traceTheLetter to reduce function complexity (ESLint compliance)
- Added SOAK_DEBUG logging for:
  - Caption box bounding box
  - Calculated drawing area
  - Screenshot dimensions (reveals 278x330 truncation)
  - Number of dark pixels found
  - Path tracing length
  - CHECK button tap result

### Verification Status

Current status: `npm run soak -- --seed 4 --lessons 8` still hits dead end

- Lessons 1-5 pass independently (npm run soak -- --seed 4 --lessons 5 → "Nothing broke")
- Dead end occurs on lesson 6, very early (after only 21 more exercises beyond lesson 5's 69)
- Dead end specifically during a trace exercise (screenshot shows "Draw over the grey letter")
- Dead end is NOT due to traceTheLetter logic failing to solve exercises
- Dead end IS due to screen not advancing after CHECK button tap on trace exercises

Test results:
- `--lessons 5`: 69 exercises, "Nothing broke"
- `--lessons 6`: 90 exercises (69+21), 1 dead end failure on lesson 6
- Dead end occurs early in lesson 6 trace exercises, not on every trace attempt

### Attempted Fixes (All Unsuccessful)

1. **Adaptive drawing area calculation** ✗
   - Changed from fixed 330px height to adaptive based on available space
   - Did NOT fix the dead end issue
   
2. **Extended wait after CHECK tap** (500ms) ✗
   - Added extra wait for app to process grade
   - Did NOT reduce or eliminate dead end
   - Suggests issue is NOT a simple race condition

3. **Centered drawing area horizontally** ✗
   - Changed x-positioning from text-based to screen-center
   - Made the problem WORSE (6 dead ends instead of 1)
   - Reverted this change

### Next Steps

The root cause requires investigation beyond soak.js. Consider:

1. **App-side trace exercise handling**: Verify that TraceExercise/TracePad correctly:
   - Processes the gestures drawn
   - Submits the grade result
   - Updates screen state after grading
   
2. **React Native gesture handling**: Check if the mouse events simulated by Playwright are being properly converted to touch events for gesture recognition

3. **Specific to lesson 6**: Isolate what's different about lesson 6's trace exercises that causes them to fail where lessons 1-5 succeed

4. **Direct exercise test**: Create a unit/integration test that specifically loads and completes a trace exercise without the soak test harness

5. **Playwright gesture alternative**: Investigate if using `touchscreen` events instead of `mouse` events would work better for React Native gesture handlers
