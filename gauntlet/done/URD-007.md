## URD-007 — Teach ذ ز ض ظ by spelling context, not by sound
attempts: 0
files: src/data/letters.ts, src/exercises/generator.ts, scripts/check-answerable.js
definition of done: These four letters are pronounced identically by most Urdu
  speakers, so a listening exercise offering two of them has two correct answers
  and is unanswerable from what it puts on screen. Either such an exercise is
  not generated, or the four are taught and tested by spelling context. Extend
  `check:answerable` to fail on any audio prompt whose options contain more than
  one of the set.
verify: npm run check:answerable
notes: Exactly the shape of the verdict-cue bug already fixed there: a question
  that cannot be answered from what is visible. Extend that check rather than
  writing a new one.

  RESOLVED: took the "not generated" branch rather than "taught by spelling
  context" — `letterPick` ("which letter makes this sound?") now never offers
  two letters that share a reading. Added `soundTokens(letter)` /
  `soundsOverlap(a, b)` to `generator.ts` (splits `letter.sound` on "/" so a
  letter with more than one reading, like alif's "a / aa", is compared
  token-by-token rather than as one opaque string) and rewrote
  `distractLetters` to pick distractors one at a time, excluding any
  candidate that shares a reading with the target *or* with a distractor
  already picked — a same-sound collision between two distractors, not just
  between a distractor and the target, is exactly as unanswerable, and the
  first draft of this fix (caught by CURRICULUM CRITIC) only excluded the
  latter. `check:answerable` gained a matching `letterPick` case, importing
  `soundsOverlap` from `generator.ts` rather than keeping its own copy.

  Computed generically from every letter's `sound` field rather than a
  hand-picked list of four, so it also closed three homophone groups nobody
  had filed against: te/toe ("t"), se/seen/swaad ("s"), and the three ه
  letters baRi-he/choti-he/do-chashmi-he ("h") — 154 real collisions across
  those plus the named four, confirmed by induced-failure testing before any
  fix, 0 after.

  THE CRITIC passed with no BLOCKING/MAJOR and three MINORs, all fixed same
  round: two stray scratch scripts left in the shared checkout by its own
  probing (deleted); `bareSound`'s definition duplicated between the two
  files instead of shared (fixed by exporting and importing it the same way
  `check-answerable.js` already imports `buildLessonExercises`); no
  dedicated unit test for the new pure logic against this project's own
  testing philosophy (added `src/exercises/generator.test.ts`).

  CURRICULUM CRITIC found a real gap in the first version's own claim to be
  generic: comparing one normalized string per letter caught "z" === "z" but
  missed that alif ("a / aa") and alif-madda ("aa") are different strings
  sharing a reading — sampled 2,902 of 3,000 real generations offering both
  together. Fixed same round by rewriting the single-string `bareSound` into
  the token-based `soundTokens`/`soundsOverlap` above, re-verified
  empirically (0/5,100 sampled `letterPick` exercises across 20 passes show
  any collision, including 0 alif/alif-madda pairs) and via a second
  induced-failure cycle against the corrected version. Also found, correctly
  not fixed here since it falls outside this item's "not generated" branch:
  none of the four ز-sound letters' `note` fields actually teach which
  letter a real word uses, only that the collision exists — filed as
  URD-038. Two further findings confirmed as pre-existing and not
  regressions, not filed: 64% of these four letters' `letterPick` questions
  offer no phonetically-adjacent distractor at all (true before this diff,
  unrelated to the same-sound exclusion); te/Te's name fields differ only by
  case, a weaker secondary cue than the other retroflex pairs get.
