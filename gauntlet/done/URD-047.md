## URD-047 — A confusable letter pair is only ever kept apart, never asked to be told apart
attempts: 0
files: src/exercises/types.ts, src/exercises/generator.ts, src/exercises/*.tsx
definition of done: URD-022 spreads a lesson's visually confusable letters
  (`daal`/`Daal`/`zaal`, `re`/`Re`/`ze`/`zhe`, and every other
  `confusableWith` pair in `letters.ts`) apart in time so they are rarely
  drilled back to back, which prevents momentary interference but never
  actually tests whether a learner can tell the two apart — the specific
  skill this item's own definition of done names ("risks teaching the
  confusion rather than resolving it"). Add a discrimination exercise kind
  that poses a `confusableWith` pair directly against each other (e.g.
  "here are ز and ذ — which one is ze?") for at least one of a lesson's
  sightings of each letter that has a `confusableWith` partner, so the pair
  is confronted directly at least once, not only ever kept apart.
verify: a test asserting every letter with a `confusableWith` partner gets
  at least one exercise, somewhere in its teaching lesson, that poses it
  directly against that partner.
notes: Found by CURRICULUM CRITIC reviewing URD-022, who judged pure
  temporal separation addresses interference-in-the-moment but not the
  longer-term discrimination skill a learner needs for two letters they
  will keep encountering. Checked for duplicates in QUEUE.md and done/ —
  none found. Not blocking — URD-022's own definition of done offered
  separation as one legitimate, complete option and the fix satisfies it;
  this is a complementary, not corrective, addition.

RESOLVED. Added a new exercise kind, `letterContrast` (`src/exercises/types.ts`,
`src/exercises/LetterExercises.tsx`'s `LetterContrastExercise`), generated by
`letterContrastExercise`/`confusableMatesIn` (`generator.ts`) and wired into
one of a letter's `SIGHTINGS_PER_LETTER` slots via `contrastRound(idx)` — a
round-selector proven, not assumed, never to coincide with the existing
context-word round (`contextRound`/`contrastRound` are the same modulus offset
by exactly +2, so `x % 4` and `(x+2) % 4` always differ). The exercise's
options are exactly the letter's own `confusableWith` bucket
(`bucketKeyOf`/base-plus-variants) and nothing else — the one thing
`letterPick`'s alphabet-wide distractors cannot test, which is discrimination
rather than recognition. A wrong answer's explanation is handled by a new
pure module, `letterContrastNotes.ts` (`contrastLine`/`contrastNotesFor`),
which guarantees — proven exhaustively in its own test, not spot-checked —
that any wrong pick shows at least one genuinely contrastive line, since
every bucket has exactly one base letter and a wrong pick is always either
the base or a variant.

**Self-caught during implementation, three defects, fixed before any critic
saw the code:**

1. `check-answerable.js`'s new per-size position-check band was too weak —
   self-caught first by noticing an 18/24-sample bucket's pass/fail flipped
   run to run on pure noise (61%→33%→48% at the same seat, no code change).
   Fixed with an `EXEMPT_PASSES` extra-sampling pass (18/24 samples raised to
   258/344) and a proper `SIGMA_LIMIT=4` z-test plus an absolute "no seat may
   be empty" rule, replacing the original relative-band idea entirely.
2. A `python3` string-replace accidentally deleted `check-answerable.js`'s
   final failure-reporting block, so the script printed failures but still
   exited 0 — caught because the exit code didn't match the printed content,
   not because any test failed. Restored the block.
3. The 3-option tile layout wrapped 2-then-1 — an orphan row, the exact
   pattern `OPTIONS_PER_QUESTION`'s own doc comment names as the reason this
   app asks four-option questions rather than five. Self-caught via a
   temporary design-harness screenshot (never committed) at 320px, the
   narrowest width `check:sizes` holds the app to.

**THE CRITIC, two MAJOR fixed at the time, one more (finding 4) delivered
later via a peer message after its own dispatch had already reported
complete once — all three resolved:**

1. The position-check weakness above (independently rediscovered from the
   check's own code, not just my noise-triggered self-catch) — confirmed
   against two of its own mutations (a 65%-biased 2-option shuffle;
   permanently-dead seats) that the original weak band passed both and the
   z-test rewrite catches both (15.8σ; "never reaches a position").
2. `check-answerable.js`'s original 40%-band comment, copied forward into
   the new exemption code before being replaced by the z-test, does not
   survive its own arithmetic (43.7/33.3 is a 31% deviation, inside a 40%
   band) — filed forward as **URD-059** rather than fixed here, since it's a
   pre-existing defect in the *main* histogram check, out of this item's
   file scope.
3. `scripts/soak.js` was never updated for `letterContrast`: no
   `NAMED_TAP_KIND`/`NAMED_KIND_SOLVER` entry (fell to the generic `'tap'`
   fallback, mislabeled and coin-flip-only), and the 3-option tile width
   (107.84px at soak's fixed 412px viewport) fell under `candidateOptions`'s
   `b.width > 110` floor. Fixed: replaced the percentage-width tiles with
   `flex-1` (three tiles always sum to exactly the row's width, so there is
   no viewport at which they wrap — confirmed at soak's 412px, 116px per
   tile, and at 320px, no wrap, both via a real screenshot, not assumed),
   and added the two-line `soak.js` fix THE CRITIC itself proposed
   (`letterContrast` reuses `answerLetterPick` verbatim, since both kinds
   render options as glyph-text buttons carrying the letter's own name on a
   separate line).

**CURRICULUM CRITIC, four MAJOR (three fixed, one filed), five MINOR (fixed
or filed):**

1. **Real regression, fixed** — introducing position-free sighting kinds
   (`letterSpot`, `letterContrast`) into the round loop let the 4-position
   joining-form cycle silently skip a step, since position was derived from
   round number rather than counted directly. Measured: the parent commit
   already had 14 of 46 letter-slots missing `final`; this item's pre-fix
   code made it worse, 25 of 46. Fixed with `nextPos`/`posSeq`
   (`generator.ts`), which counts position-bearing sightings rather than
   rounds — result measured at 4 of 46, better than the parent commit's own
   14. Revert-verified: reverting `nextPos` reproduces exactly 25.
2. A reveal-panel `accessibilityLabel` overrode the glyph a screen reader
   would otherwise announce with a position the learner already knew
   ("Letter option 1 of 2") — removed, matching `letterPick`'s own
   unlabelled tiles in the same file, with the reasoning left as a comment
   so it isn't quietly re-added.
3. The residual joining-form gap underneath fix 1 (4 of 46 still missing
   `final`, 36 of 46 missing at least one of the four forms) is a real,
   larger, pre-existing shape than this item's own regression — filed
   forward as **URD-060** rather than expanded here, since closing it needs
   the kind/position interaction redesigned (a fourth position-bearing slot,
   or giving `letterPick` a position), not another counter fix.
4. `letterContrast` is reachable only from a letter's own teaching lesson,
   never from review — filed forward as **URD-061**, judged the most
   serious finding against BENCHMARKS.md's own spacing standard (every other
   skill in the app is spaced; this one is drilled twice in one day and
   never again). Not fixed here: reaching review means `reviewLetterPool`
   would need to know about confusable buckets, real design work rather
   than a call-site change.
5. The 13 base letters' own `note` text describes the letter standing alone,
   not the mark separating it from its variants — for two (`kaaf`, `seen`)
   the note reads as *endorsing* a wrong answer just tapped. Filed forward
   as **URD-062** (also independently found by THE CRITIC) — needs new
   content in `letters.ts`, out of this item's file scope.
