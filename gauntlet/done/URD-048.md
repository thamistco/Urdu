## URD-048 — Raise sentences-lesson size to close more of the reachability ceiling
attempts: 0
files: src/data/units.ts
definition of done: `S()`'s default `size` (units.ts) is 8, costing 45s of
  exercises per sentence (`sentenceReinforceClimb`, URD-025) — 6.0 minutes
  at size 8, comfortably under check:shape's 8-minute ceiling (up to 10.67
  sentences fit, 450s). Raise it to 10, the largest value still inside the
  band, verified directly against real generated output (not estimated):
  moves course-wide reachable coverage from 96/256 (37.5%) to 115/256
  (44.9%) with zero check:shape length/share/run violations introduced.
  Full parity (matching every level's whole pool) is out of reach this way
  — elementary alone would need size 35, ~26 minutes, more than 3x the
  ceiling — so this closes part of the gap, not all of it, and should say
  so rather than be mistaken for a complete fix.
verify: npm run check:sentence-coverage (ceiling rows should show higher

  RESOLVED: `S()`'s default `size` changed 8→10. Real, measured result:
  116/256 (45.3%) reachable, not the pre-implementation estimate of
  115/256 — the difference is a real discovery, not rounding: raising the
  size exposed a genuine position-scarcity case `sentencesForLesson`
  (URD-027) had never hit at size 8. `s-intermediate` and
  `s-intermediate-2` (adjacent units, u12/u13) share a readable-at-position
  pool of only 16 sentences — confirmed by THE CRITIC that essentially
  nothing new becomes readable between them (contrast `s-advanced`→
  `s-advanced-2`, also adjacent, whose readable pool grows 13→23) — too
  thin to supply both lessons' combined 20 slots distinctly. The
  function's old fallback silently allowed reusing a sibling's already-
  claimed sentence when its own unclaimed pool ran short, reintroducing
  the exact "a sibling repeats what another already showed" defect
  URD-027 exists to prevent — this had never fired at size 8 (confirmed:
  THE CRITIC found the minimum readable-and-unclaimed pool anywhere at
  size 8 was comfortably above every lesson's needs).

  Fixed at the root rather than patched: `sentencesForLesson` never reuses
  a claimed sentence now, even if that leaves a lesson short of its
  designed size — `s-intermediate-2` draws 6 of its designed 10, and nowhere
  else falls short. `scripts/check-sentence-coverage.js` (URD-027) was
  rewritten to assert the correct, narrower invariant this exposed: zero
  overlap between siblings (the union of picks equals the sum of each
  lesson's own distinct draw), not "every lesson always reaches its
  designed size" — the old assertion would have called this honest,
  correct behavior a regression. `generator.test.ts`'s matching unit test
  was updated the same way.

  THE CRITIC (mandatory) found two MAJOR issues, both fixed:

  (1) `units.ts`'s own doc comment for this change still quoted the
  pre-discovery estimate (96/256→115/256) after the real, verified number
  (116/256) was known — the same shape of mistake this project's own
  non-negotiable #4 names (a comment that stopped matching what was
  actually measured). Corrected to the real number, with a note explaining
  why it differs from the estimate.

  (2) an unrelated, pre-existing bug making `check:all` itself flaky:

  (same spelling, different meaning; 40 such pairs exist across the
  2,281-word vocabulary) can land in the same option set, and an unseeded
  shuffle means which pair collides, if any, differs run to run. THE
  CRITIC measured `check:answerable` failing ~3 of 10 standalone runs,
  each time citing a different, unrelated id. Confirmed entirely unrelated
  to this item's diff (reproduces with plain vocabulary, no sentence
  content involved) and not a duplicate of URD-013 (a different unseeded-
  shuffle call site, already closed) — filed forward as URD-049 rather
  than fixed here, flagged high-priority since it undermines every other
  item's own `check:all` verification until fixed. Confirmed, before
  shipping this item, that `check:answerable` passed 3 standalone reruns
  and a full, clean `check:all` run.

  THE CRITIC also verified: the adjacency really is an isolated content
