## URD-071 — do-chashmi-he's note correctly explains its own function, but that text was never shown to a learner during real play

**Status: RESOLVED**

### The gap

`do-chashmi-he`'s `note` field correctly states its actual function — "it
aspirates the letter before it (k→kh, b→bh)" — a silent modifier on the
*preceding* consonant, not a standalone sound. CURRICULUM CRITIC traced the
real render path and found that explanation never reaches a learner:
`letter.note` renders in exactly one place in the whole app
(`LetterLabScreen.tsx`, already documented elsewhere in this corpus as
flashcard trivia outside the real lesson path). The one mechanism that
surfaces note text *during* real play, `letterContrastExercise`, is gated
strictly by `confusableWith` buckets — which `do-chashmi-he` correctly has
none of (URD-067). Every real exercise instead shows only `name` and the
bare, untranslated jargon in `sound` ("h (aspirate)") — a learner sees that
phrase repeated across all 6 real sightings in lesson `l-8` and is never told
what "aspirate" means or that ھ changes the letter before it.

### Measuring the actual scope

Per the item's own instruction ("measure, don't assume... since do-chashmi-he
is likely not the only one affected"), scanned all 40 letters' `note` fields
for the same textual pattern — a letter described as changing a
*neighbouring* sound rather than carrying one of its own:

```
$ node -e "... /before it|never stands alone|modifies|doubles as/i ..."
noon-ghunna      | A dotless noon at the end of a word, it nasalises the vowel before it.
waw              | A round head with a tail. It never joins forward, and doubles as the vowels o and u.
do-chashmi-he    | The h with two eyes. It never stands alone in meaning, it aspirates the letter before it (k→kh, b→bh).
```

Exactly two letters share the exact affected pattern — `do-chashmi-he` and
`noon-ghunna`, both "silent modifier of the letter/vowel right before it,"
both carrying the same unexplained bracketed jargon in `sound` ("aspirate",
"nasal"). `waw` is a different, already-adequately-exposed case: its `sound`
field is `'w / o / u'` — the dual-vowel-role fact is stated directly in the
one string every real exercise already shows, no jargon hiding it. `ain`
("silent") and `hamza` ("glottal") were checked and excluded too: `ain`'s tag
is plain English a beginner already understands, and `hamza` doesn't modify
anything else — it's a standalone catch, not a modifier, so it doesn't carry
the specific confusion this item is about.

### The fix

`confusableWith` is documented as, and stays, a visual-shape mechanism — per
CURRICULUM CRITIC's explicit finding, linking these letters there was
rejected in URD-067 and would misrepresent an unlike pair as near-identical
outlines to the `letterContrast` UI. Instead, a new optional field,
`Letter.functionNote` — a short, plain-language translation of the jargon,
set only on `do-chashmi-he` and `noon-ghunna`:

```ts
functionNote: 'Silent on its own. It changes the sound of the letter right before it (k→kh, b→bh).'   // do-chashmi-he
functionNote: 'Silent on its own. It nasalises the vowel right before it.'                              // noon-ghunna
```

Rendered in `LetterFormExercise` (`LetterExercises.tsx`) — the one exercise
kind that already has this exact "reveal a short fact after answering"
convention, for a different case (`pickedATwin`, a non-connector's
look-alike positions). Reusing it rather than inventing a new one:

```tsx
{picked != null && letter.functionNote && (
  <Txt className="mt-1 text-center text-xs text-paper/55">{letter.functionNote}</Txt>
)}
```

Shown every time the letter is met (not gated on a "first sighting" the app
has no infrastructure to track), matching this app's own design philosophy of
reinforcement through repetition rather than a one-off tooltip.

### A real house-style gap this surfaced

The first draft of both `functionNote` strings used an em dash ("Silent on
its own — it changes..."). `npm run check:writing` passed — but only because
`functionNote` isn't in `COPY_KEYS`, the hand-maintained list of field names
the check actually scans. A brand new user-facing field was invisible to the
one check that exists to hold user-facing prose to house style — confirmed by
deliberately re-introducing the dash after registering the field and watching
`check:writing` catch it:

```
$ node scripts/check-writing.js   # functionNote field NOT yet in COPY_KEYS
check:writing — no dashes and no typewriter quotes in any user-facing string.
  (false pass — the field was never being scanned)

$ node scripts/check-writing.js   # functionNote registered, dash reintroduced
check:writing — 1 user-facing string(s) break the house style:
  src/data/letters.ts:582  [functionNote dash]  Silent on its own — it nasalises ...
```

Fixed both strings to use two sentences instead of a dash, and added
`'functionNote'` to `COPY_KEYS` in `scripts/check-writing.js` so the next
author who adds a dash here gets caught, rather than the field staying a
permanent blind spot the way it was for this diff's own first draft.

### Verification

Three tests in `src/data/letters.test.ts`, tying `functionNote`'s presence to
the exact textual signature the finding turned on ("before it" in the note),
in both directions:

```
$ npx vitest run src/data/letters.test.ts
  Tests  19 passed (19)
```

Mutation-tested, per non-negotiable #2:

| mutation | fails |
| --- | --- |
| remove `functionNote` from `do-chashmi-he` | the 2-letter count test, and the "names what it changes" test |
| add a `functionNote` to `kaaf` (no "before it" in its note) | the 2-letter count test |
| make `noon-ghunna`'s `functionNote` a verbatim copy of its `note` | the "real translation, not a copy" test |

Confirmed live, against a freshly rebuilt `dist/` (the first attempt tested a
stale build from before this session's own changes and showed nothing — a
real process trap worth flagging: `soak.js` never rebuilds `dist/` on its
own, so a code change with no `npm run build:web` in between silently tests
old code). Drove a real lesson to `do-chashmi-he`'s `letterForm` screen
(`--start 66`, lesson `l-8`'s real index in `ALL_LESSONS`) and captured the
rendered result:

> "Silent on its own. It changes the sound of the letter right before it
> (k → kh, b → bh)." — rendered centered, on two lines, directly below the
> answer choices, exactly where `pickedATwin`'s reveal already appears for
> other letters.

```
$ npx tsc --noEmit / npm run lint / npm run format:check
  clean.
$ node scripts/check-writing.js
  clean (functionNote now scanned).
```

### What this does not fix

`ain` and `hamza`'s own bracketed jargon ("silent", "glottal") were checked
and deliberately excluded — see "measuring the actual scope" above. If a
future review disagrees with that exclusion, it should be argued on its own
evidence, not folded into this item's scope.
