## URD-020 — Letter lessons are almost entirely isolated-glyph recognition
attempts: 0
files: src/exercises/generator.ts
definition of done: Across all 9 letter lessons, `letterTrace` + `letterForm`
  + `letterPick` account for 276 of 285 exercises (96.8%); the remaining 9
  are one context word per lesson. A learner meeting a completely new script
  spends nearly all of their first hours on isolated glyphs and almost none
  reading them inside real words. Raise the share of exercises that show a
  letter inside an actual word — more than one context word per lesson, or a
  dedicated "spot the letter in this word" exercise kind — without raising
  total lesson length past the 3-8 minute band check:shape already holds
  letter lessons to.
verify: npm run check:shape -- --kind=letters
notes: Found by the CURRICULUM CRITIC across two review rounds of URD-013,
  confirmed unchanged by every fix in that item (the ratio was identical
  before and after, since none of the three critique rounds touched exercise
  *kind* composition, only ordering and scheduling). The interleaving fix
  made the same lopsided material better *spread*, not less lopsided.

  RESOLVED: every letter now gets its own context-word sighting — one of
  its 6 total sightings — instead of one shared context word for the whole
  lesson. `LETTER_CONTEXT_WORD` (`generator.ts`) matches each letter's own
  glyph (`forms.isolated`) as a literal substring against the real `WORDS`
  corpus, preferring the lowest CEFR level, and preferring a word not
  already assigned to another letter in the same teaching group so two
  letters in one lesson don't get handed the identical word. `contextRound`
  places the sighting at one of rounds 1-5 (never round 0), replacing an
  isolated sighting rather than adding one. Measured directly on real
  generated output: isolated share fell from 96.8% to 83.3%, in-context rose
  from 3.2% to 16.7%, total exercise count unchanged (one shorter, if
  anything, since the old single shared context word is gone).

  THE CRITIC found BLOCKING, on the first draft: it drew context words from
  a new 40-word corpus built from each `Letter`'s own curated `word` field
  (already shown on `LetterLabScreen`, never before used by a teaching
  lesson) — but those ids existed nowhere in `voiceManifest.ts`. A
  `listenTap` review question built from one of these — reachable once such
  a word is SRS-graded and comes due, which real play reaches — showed only
  a "tap to hear" prompt with no text fallback, asking the learner to
  identify a word from audio that did not exist. Reproduced live via a
  constructed due-queue scenario. No existing check could have caught it:
  `check-voice.js`'s speakable list never knew the new pool existed (it
  reported "2720/2720 covered," a denominator that silently excluded every
  new id), `check-answerable.js` never builds a due queue, `check-shape.js`
  only builds due queues from real lesson word/letter ids.

  Rebuilt rather than patched: `LETTER_CONTEXT_WORD` now draws only on real
  `WORDS` entries — every one already has a real, already-required voice
  clip, so nothing new needed recording. Re-verified exhaustively (not
  sampled) by THE CRITIC in a second pass: all ~40 entries resolve through
  `getWord` and appear in the voice manifest.

  CURRICULUM CRITIC found two more real issues, both fixed: (1) the first
  draft's `contextRound` formula put the first letter's context sighting at
  round 0 whenever a lesson wasn't a later sibling — true for 8 of the 9
  real lessons, including the very first lesson in the course — making a
  whole unfamiliar word the learner's literal first exercise, before the
  taught letter had been isolated-introduced even once. Fixed: `contextRound`
  now always lands in rounds 1-5, guaranteeing the round-0 sighting is
  always the isolated introduction. (2) `gaaf`'s naive best-match word,
  گھر ("ghar", house), puts گ directly before `do-chashmi-he` (ھ) — an
  aspirating "gh" digraph, a different sound than gaaf's own plain "g."
  Fixed with a general guard (not a one-letter special case): a match
  immediately followed by the aspirate glyph is avoided wherever a clean
  match exists for that letter.

  Also found `baRi-ye`'s pre-existing curated example word (میز, "table")
  does not contain baRi-ye's own glyph anywhere — a data bug predating this
  item, newly reachable because a generator search over `Letter.word` would
  have promoted it into a real, graded exercise (it was already live,
  unfixed, on `LetterLabScreen`). Fixed in `letters.ts` — twice: the first
  replacement, چائے ("tea"), turned out to already be `hamza`'s own curated
  example, caught by `npm run audit`'s example-word-collision rule (part of
  `check:all`) rather than by any review round; replaced again with جوتے
  ("shoes"), which collides with neither.

  A second THE CRITIC pass, dispatched after this full redesign given its
  scale, confirmed the BLOCKING finding fully closed and found no new
  BLOCKING. Three MINOR gaps, all addressed: nothing had locked in that two
  letters in one lesson never share an identical word (a first version of
  the group-distinctness fix could still produce this under a different
  fallback order) — added a direct regression test; a doc comment
  overclaimed two letters "never" land on the same context round — corrected
  to state the real, harmless exception for groups over 5 letters (l-1,
  l-1-2, l-3); `check-shape.js`'s new per-letter rule would silently skip a
  hypothetical letter with zero real matches — left as-is since the vitest
  suite's count-based test already independently catches that case.

  This fix also fully resolves URD-021 ("a letter group's context word
  should touch more than its first letter") as a side effect — closed
  separately, see its own done/ entry.

  Verified via induced failure four times over: reverting `contextRound` to
  allow round 0 reproduced the cold-open bug exactly; reverting the group-
  distinctness guard collapsed l-1's 6 distinct context words to 4,
  reproducing the shared-word bug; dropping the context-round mechanism
  entirely reproduced the `check-shape.js` share-floor failure across all
  9 lessons; and dropping one specific letter's assignment directly first
  produced a false negative in the check-shape.js per-letter rule's own
  first draft (the exact discovery that led to fixing that rule to match
  by word id instead of loose glyph presence) before correctly failing once
  fixed. All four restored and reconfirmed clean. Full `check:all` (26
  steps, including `npm run audit`), `check:answerable` (107,556 exercises),
  `check:coverage`, and `check:voice` all pass on the final tree.
