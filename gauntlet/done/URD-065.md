## URD-065 — check:theme's withAlpha rule cannot see a faded text colour reached through a variable

**Status: RESOLVED**

### Implementation

Added `checkVariableWithAlpha()` function to `scripts/check-theme.js` that:

1. Finds all `const/let/var X = ... withAlpha(palette.paper, N) ...` variable declarations
2. For each such variable, searches the following scope (until the next closing brace) for uses in `color:` or `placeholderTextColor=` assignments
3. Reports violations when the alpha value is below the 55% legibility floor

### How it works

The function uses a forward-data-flow trace approach:
- Parses variable declarations containing `withAlpha(palette.paper, N)`
- Extracts the variable name and alpha value
- Searches for uses of that variable in text-colour props within the same scope
- Reports the variable's usage line with context about the underlying alpha value

This catches the pattern that `Button.tsx` uses for computing multiple colours:
```javascript
const text = disabled ? withAlpha(palette.paper, 0.55) : TEXT[variant];
// ... later in the component
<Bold style={{ color: text }} ...>
```

### Scope boundaries

The search scope extends from the variable declaration to the next closing brace (`}`), which roughly corresponds to function scope in most cases. This is a conservative approach that avoids false positives from variables that might be reused in different functions.

### Testing

Verified against real code:
- `Button.tsx` line 112: `const text = disabled ? withAlpha(palette.paper, 0.55) : TEXT[variant];`
- Temporarily changed 0.55 to 0.4 (below the floor)
- `npm run check:theme` correctly reported violations at lines 166 and 170 where `text` is used in style props

### Edge cases handled

- Only reports violations for values below 55% floor (0.55 and above pass silently)
- Properly calculates alpha values as percentages (0-1 fractions converted to 0-100)
- Handles variable reuse by scoping to the next closing brace
- Works with both simple variables and ternary assignments
