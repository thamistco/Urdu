## Q-019: the cause, the fix, and what kept it hidden

- **The probe.** The upgrade was reapplied on the live commit and passed check:all here. It was then pushed on purpose as 6e13e99c, knowing CI might fail (run 41368442198): a failed build skips the deploy, so the live site could not change. CI failed. The never-rendered check, which now prints the page's errors (87ed7a91), said: `HeadlessChrome/131 … page error: Cannot use 'import.meta' outside a module`.
- **The cause.** From SDK 54 Metro resolves packages' ES-module builds. zustand's devtools middleware reads `import.meta.env`, and the bundle loads as a classic script, where that is a syntax error.
- **Why it never showed here.** Metro's cache on this machine still held transforms from before the upgrade, so every build here was free of `import.meta`. That covers check:all, both nights' second checks, and every probe. A build with `--clear` had the same four uses CI's had.
- **The fix** (f84d42b2): babel-preset-expo's `unstable_transformImportMeta`. A clean build now has none.
- **The cause of the cause** (fe2b7920): `build:web` now clears the cache on every build, as CI's fresh machine does. A clean export measured 124s.
- **A check for the class** (693369a9): `check:classic-script` parses every script the page loads exactly as a classic script. It fails on the unfixed clean build, naming `import.meta` and its offset, and passes on the live SDK 52 build and on the fixed one.
- **Shipped.** fe2b7920 passed check:all here (43 steps) and CI, and its deploy's "Verify the live site is serving this commit" succeeded.
