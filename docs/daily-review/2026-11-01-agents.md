## After the push: CI's browser, and the hold

The final tree passed check:all here (all 42 steps) and was pushed as beff0362. CI's run 41262309184 then failed at check:stability with "the app never rendered a screen: 20s after loading, the page still holds 0 characters". The deploy step was skipped, so the live site stayed on 3e4b7b98 throughout.

The difference is the browser. Here, every check and the second check drive Chromium 153. CI drives the Chromium 131 headless shell that Playwright 1.49 installs. The bundle parses under Node 22's V8, which is about Chrome 124, so the cause is something at runtime that Chromium 131 lacks. A search for newer built-ins found nothing new in the bundle. A Chrome 131 to reproduce with could not be fetched here, because the permission system refused the download. So the cause is not known.

A learner on an older browser would meet the same blank page. So the upgrade is held, not forced:

- The three SDK 54 commits are reverted in one commit (b64dc808) and saved as `held/Q-019-expo-sdk54-2026-11-01.patch`.
- What works on either SDK stays: nested licence paths, the tab focus subscription and the test-out copy.
- The never-rendered check now reloads the page with listeners on and prints the browser and its errors. It was seen working on a bundle broken on purpose.

The next try should start by pushing nothing. Instead, build the held patch, serve it in CI's browser, read the error, and fix it there.
